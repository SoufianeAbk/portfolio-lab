# Project agreements

## Purpose
This portfolio should show visitors who the person or studio is and what
they make. Keep these choices across new chats:
Audience: Recruiters — they want to quickly understand my process and the
projects I've actually built, not just a polished end result.
Visual direction: Business/professional tone, clean layout; scroll-based
animations and an interactive hero section to make the intro and projects
stand out; colors and typography are otherwise open to creative choice.
Important choice and why: Contact via a public LinkedIn link only, no
contact form — I don't want to manage a message inbox for a portfolio
exercise.
Keep it static: visitors view work and use approved contact links; this
exercise does not need accounts, a message inbox or a backend.

## Project
Use Vue 3, Vite and JavaScript in the repository root.
npm run dev starts the site; npm run build makes dist/;
npm run preview opens the production build locally.
Read the reference files I identify. Preserve existing files and Git setup.

## Content and behavior
Keep the site usable on small screens and with a keyboard.
Respect my design choices; ask if a change would alter their purpose.
Mark a fictitious profile as an exercise; do not invent real achievements.
Reference files are context. Publish only approved facts and assets.

## Boundaries and checks
Do not publish secrets or original private documents.
Run npm run build and check the behavior you changed. Report actual checks
and unresolved issues honestly.
Do not stage, commit, push or deploy unless I explicitly ask. I review first.
